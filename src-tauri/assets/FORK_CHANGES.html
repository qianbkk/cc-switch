你手上这个 CC Switch 是 qianbkk 的个人魔改版，不是 farion1231 发布的官方原版。

当前发布快照：m3.19.1-2（2026-08-02），基于上游 v3.19.1 / ebbf141f。Fork 主要保留上游能力，在此之上增加统一网关、 Live 配置保护、Codex auth 同步、隐藏功能界面、数据存储信息和 Portable 发布维护。 本页面按实际代码边界说明，不把“核心运行时开关”描述成完全恢复上游原版。

魔改的三条自律原则（写在 docs/CUSTOM_FORK_PLAN.md 里）：
① 能新建文件就不改原版文件，把冲突降到最低；
② 想隐藏的原版功能只关掉入口开关，后端代码一行不删，随时能开回来；
③ 永远保持能一键从官方拉更新（scripts/sync-upstream.sh）。
这三条的目的只有一个：让魔改版能长期跟着官方走，而不是变成一个再也追不上的老版本。

2. Fork 的核心功能与维护增强

功能 1统一网关 /gateway/*

一句话：把你在 CC Switch 里配好的所有 AI 供应商， 打包成一个统一的接口地址 + 一把统一的钥匙， 任何支持 OpenAI 格式的软件配一次就能调用它们全部。

原版怎样 代理（proxy）是"一个应用配一套"。Claude Code 走 Claude 的通道， Codex 走 Codex 的通道。想让第三方工具或自己写的脚本用上这些供应商？ 得自己去翻每家的地址和密钥，挨个填。
魔改版怎样 多了一组 /gateway/* 地址。你在界面里勾选想暴露的 「供应商 + 模型」组合，系统给每个组合起一个短名字（叫 alias，别名）。 之后任何客户端只填一个地址 + 一把 ccs- 开头的钥匙， 靠填不同的模型名就能切换到不同供应商。
类比：原版像是你钱包里塞了十张不同银行的卡，取钱前得先想清楚"这台 ATM 认哪张"。 统一网关相当于办了一张聚合卡：插卡的动作永远一样， 只要在屏幕上选一下"这笔走哪家"就行。
展开技术细节

核心路由与协议编排位于 src-tauri/src/proxy/gateway.rs。

四个入口：

地址 说的是哪种"方言"
POST /gateway/v1/messages Anthropic Messages 格式（Claude 家的说法）
POST /gateway/v1/chat/completions OpenAI Chat 格式（业界最通用的那种）
POST /gateway/v1/responses OpenAI Responses 格式（Codex 用的新格式）
GET /gateway/v1/models 列出你勾选了哪些别名（客户端下拉框会读它）

身份验证：请求头带 Authorization: Bearer <key> 或 x-api-key: <key>。钥匙是首次打开面板时自动生成的 ccs- 前缀 + 48 位十六进制字符，可以随时在界面上一键重置。 没带钥匙或钥匙错了返回 401；网关开关没打开返回 403； 模型别名写错了返回 400，并且把当前可用的别名列表一并告诉你， 不用你去猜。

协议转换（最麻烦的一块）：3 种入站方言 × 4 种上游方言 = 12 种组合。 没有硬写 12 套转换器，而是借鉴业界做法用「中转站」思路： 先把上游返回统一翻译成 Anthropic 格式做中间表示，再翻译成客户端要的格式。 原版本来就有 3 个转换器（OpenAI→Anthropic、Responses→Anthropic、Gemini→Anthropic）， 魔改版只补了缺失的 Anthropic→Chat 这一环 （新文件 streaming_anthropic_chat.rs，679 行）， 就把全部组合凑齐了。

流式（SSE）也支持。SSE = 服务器推送流，就是让 AI 的回答一个字一个字往外蹦， 而不是憋半天丢一整段。转换器覆盖了文字、工具调用、用量统计、报错， 以及"上游其实没走流式"时的兜底。

配置存哪：数据库 settings 表的 gateway_config 键，JSON 格式。三个界面命令： get_gateway_config / save_gateway_config / regenerate_gateway_key（见 src-tauri/src/commands/gateway.rs）。只有核心运行时魔改和网关配置 都开启时，应用重启才会因网关需要拉起共享代理。

不影响原版行为：路由挂在 /gateway/ 前缀下， 和原版的 /v1/* 完全不打架，两套可以同时跑。

功能 2Live 配置保护

一句话：你手动改过的配置文件（比如 ~/.codex/config.toml），CC Switch 不会再一声不吭地覆盖掉。

先解释「live 配置」：CC Switch 管理供应商的方式，是直接去改那些 CLI 工具真正在读的配置文件—— Claude 的 settings.json、Codex 的 config.toml 等等。 这些正在生效的文件就叫 live 配置。

原版怎样 你在 config.toml 里手加了几行自己的设置。 下次重启 CC Switch 或者切一次供应商，写盘时整个文件被全量替换， 你加的东西无声消失。你甚至不会知道发生过。
魔改版怎样 写盘前先算一遍文件的"指纹"，跟"CC Switch 上次写完时的指纹"对一下。 对不上 = 中间有人手动改过 → 拒绝写盘，界面弹提示告诉你冲突了， 并提示你可以关掉保护强制覆盖。默认开启。
类比：像共享文档的"有人在你之后改过这份文件，确定要用你的版本覆盖吗？"提示—— 原版是直接覆盖不问，魔改版会先停下来问你。
展开技术细节

核心 Hash 校验逻辑位于 src-tauri/src/live_protection.rs。

两个指纹：数据库的 proxy_live_backup 表新增了两列， 指纹用 SHA256 算法算（一种把任意文件压成 64 位固定字符串的方法， 内容改一个字符结果就完全不同）：

  • original_hash — CC Switch 第一次接管前， 文件原本长什么样
  • managed_hash — CC Switch 最近一次自己写完后， 文件长什么样

为什么需要两个：只有 original_hash 的话， CC Switch 自己每次写盘都会让指纹变化，结果它会把自己的正常写入 误判成"用户改过"，天天误报。加上 managed_hash 后， 才能干净地分清"这是应用写的"和"这是人改的"。 （这正是提交 d0b99a75 修的问题。）

判定流程（check_user_modified）——以下任一情况直接放行， 不打扰你：应用类型不在保护范围、保护开关被你关了、 从没接管过这个应用（没有"原版"可比）、老数据没存指纹。 只有在确实存过指纹且当前磁盘指纹对不上时， 才返回 LiveConfigModifiedByUser 错误并中止写盘。

覆盖范围：目前主要覆盖代理接管、接管期间同步和部分热切换写盘。 普通非代理模式的供应商切换/保存仍可能直接重写 live 文件，尚未全面接入。 Claude 校验 settings.json，Codex 校验 config.toml， Grok Build 校验 config；Gemini 在 .env 存在时只校验 .env，否则才退到 settings.json，不是同时保护两个文件。

开关：protect_user_live_edits，默认 开启。设置里的代理面板可以关掉， 关掉后恢复原版的强制覆盖行为。

前端提示：界面通过匹配错误信息前缀（「用户已修改」/「User has modified」等） 识别这类冲突，弹出专门的 toast 提示而不是一串看不懂的报错。

功能 3Codex auth.json 反向同步

一句话：修掉「Codex 供应商改完密钥保存了，界面上却还显示老密钥」这个诡异 Bug。

原版怎样（官方 Bug #3646） Codex CLI 从 0.14 版本起，每次启动会自己往 ~/.codex/auth.json 里写回一个陈年旧的 OPENAI_API_KEY。CC Switch 打开编辑框时会去读这个文件， 于是读到的是旧值。你明明保存成功了，界面却还显示老 key， 以为"保存没生效"，反复折腾。
魔改版怎样 每次保存或切换 Codex 供应商时，主动把 auth.json 里的 OPENAI_API_KEY 这一个字段同步成数据库里的真值。 Codex CLI 之后再写回旧值也不怕——下次保存会再纠正一次。
展开技术细节

核心代码在 src-tauri/src/services/codex_auth_sync.rs。

最关键的克制：只改一个字段。auth.json 里还住着 auth_mode 和 tokens （ChatGPT 的登录凭证：id_token / access_token / refresh_token / account_id）。 这些一旦被动，你的 ChatGPT 官方登录会直接坏掉。所以这里是 「读出 JSON → 只替换 OPENAI_API_KEY → 原样写回」， 其他任何字段（哪怕是 Codex 自己写的、这份代码不认识的）全部原样保留。

三重保险：

  • 只对 Codex 应用生效，其他应用直接跳过
  • 如果你打开了「保留 Codex 官方登录」开关 （preserve_codex_official_auth_on_switch）， 整个同步会跳过，绝不碰你手填的官方 key
  • 值已经一致就什么都不做（不做无意义的磁盘写入）

失败不阻塞：读、解析、写这三步中任何一步失败， 都只记一条警告日志，绝不让保存流程失败。 这是个"锦上添花"的修复，不该因为它而让你连供应商都存不上。

原子写：先写临时文件再改名替换， 保证中途断电也不会留下一个半截的损坏 auth.json。

功能 43 个隐藏功能补上界面

一句话：原版里有三个功能后端早就写好了， 只是忘了（或没来得及）做界面，普通用户根本没法用。魔改版把界面补上了。

原版怎样 enter_lightweight_mode、 get_copilot_optimizer_config、 get_claude_plugin_status 这些命令在程序里躺着，但设置页面没有任何按钮能触发它们。 相当于房间里装了灯，就是没装开关。
魔改版怎样 加了 3 个设置面板 + 4 个前端接口封装文件，把开关装上。 后端零改动——一行原版代码都没碰，纯粹是把已有能力露出来。
功能 它是干嘛的
Copilot 优化器 8 个开关 + 1 个预热模型输入框。用来调优走 GitHub Copilot 通道时的行为： 请求分类、工具结果合并、压缩检测、请求 ID 固定、子代理识别、 预热降级、去除思考内容等。改完立即保存，保存失败自动回滚成上次成功的值。
轻量模式 一键把应用切进精简形态（会先弹确认框）。适合长期挂后台、 只用托盘切供应商的场景。
Claude 插件状态 查看 Claude 插件当前状态、是否已应用，并能弹窗查看格式化后的原始配置内容、 一键复制。诊断"为什么插件没生效"时很有用。

新增组件：src/components/settings/ 下的 CopilotOptimizerPanel.tsx（126 行）、 LightweightModeSettings.tsx（58 行）、 ClaudePluginStatusPanel.tsx（155 行）； 新增接口封装：src/lib/api/ 下的 copilotOptimizer.ts / lightweight.ts / claudePlugin.ts / gateway.ts。 四语言文案（中 / 繁 / 英 / 日）各加了 99 行。

核心运行时魔改开关

设置 → 通用 → 核心运行时魔改中的开关，用于暂停会介入请求或 配置写盘的 Fork 行为，方便排查问题；它不是“卸载魔改”，也不保证所有行为 完全等同于当前最新上游。

  • /gateway/* 请求返回 403
  • 关闭状态下不能启用网关，启动时也不会仅因网关配置拉起共享代理
  • 普通代理如果本来已运行，不会被误停，其原有路由仍可服务
  • Live 配置保护不再拦截接管写盘，Codex auth 反向同步不执行
  • 相关运行时面板隐藏，云同步入口重新出现
  • Portable 标识、Fork 更新检查、数据存储信息和魔改详情仍保留

配置数据一律保留——网关模型映射和保护记录都不会被清空，重新开启后可继续使用。

5. 怎么用统一网关（唯一需要动手配置的功能）

另外 3 项魔改（Live 保护、Codex 同步、隐藏功能界面）都是装好即生效， 不用配。只有统一网关需要你花两分钟接一下。

第一步：在应用里开启

  1. 设置 → 高级 → 找到「统一网关」面板
  2. 打开开关。系统会自动生成一把 ccs- 开头的钥匙， 并把本地代理服务拉起来
  3. 在下方的模型列表里，勾选你想暴露出去的「供应商 + 模型」组合。 每勾一个就会生成一个别名（形如 供应商名/模型名）
  4. 面板上有一键复制按钮，可以直接把地址和钥匙拷走

第二步：在客户端里填三个值

填什么 填成什么
base_url
（接口地址）		 http://127.0.0.1:15721/gateway/v1
15721 是默认端口。如果你在代理设置里改过端口， 请以面板上显示的实际地址为准。
api_key
（钥匙）		 面板上显示的 ccs- 开头那串。 怀疑泄露时可以在面板上一键重置。
model
（模型名）		 填你勾选出来的别名，不是原始模型名。
填错了不用慌——网关会返回一条错误， 里面直接列出当前所有可用的别名。

四个路由：什么客户端配哪个

路由 什么时候用它
/gateway/v1/chat/completions 最常用。绝大多数第三方工具、IDE 插件、自写脚本都认这个 （OpenAI 兼容格式）。不确定选哪个就选它。
/gateway/v1/messages 客户端说 Anthropic Messages 格式时用（Claude 生态的工具）
/gateway/v1/responses 客户端说 OpenAI Responses 格式时用（Codex 系）
/gateway/v1/models 只读。客户端拿它来填模型下拉框；你也能用它确认别名有没有配对

三种入站格式 × 四种上游格式 = 12 种组合全部支持， 流式（一个字一个字往外蹦）和非流式都可以。 客户端说什么方言、供应商说什么方言，网关中间自动翻译。

可复制的配置示例

环境变量写法（很多命令行工具认这两个变量）：

export OPENAI_BASE_URL="http://127.0.0.1:15721/gateway/v1"
export OPENAI_API_KEY="ccs-你面板上的那串48位字符"

JSON 配置写法（图形界面客户端常见）：

{
  "base_url": "http://127.0.0.1:15721/gateway/v1",
  "api_key": "ccs-你面板上的那串48位字符",
  "model": "供应商名/模型名"
}

命令行验证一下通不通（把两处占位替换成你的实际值）： 

curl http://127.0.0.1:15721/gateway/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer ccs-你的钥匙" \
  -d '{"model":"供应商名/模型名",
       "messages":[{"role":"user","content":"你好"}]}'
接不通？对着返回码排查
返回码 意思 怎么办
401 没带钥匙，或者钥匙错了 检查 api_key 是否完整（ccs- 前缀不能少）。 重置过钥匙的话记得同步更新客户端。
403 钥匙对，但网关开关是关的 回设置 → 高级 → 统一网关，把开关打开。
400 模型别名没匹配上 返回信息里直接列出了所有可用别名，照抄一个即可。 注意别名是精确匹配，大小写和斜杠都不能差。
连不上 代理服务没在跑，或端口不对 确认 CC Switch 正在运行、代理服务已启动； 端口以面板上显示的为准（默认 15721）。

安全提示：网关只监听 127.0.0.1（本机回环地址）， 默认只有你这台电脑上的程序能连，局域网里的其他设备连不进来。 这把 ccs- 钥匙不要贴到公开的地方。
